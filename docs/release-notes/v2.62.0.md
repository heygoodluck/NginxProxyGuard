## ⚠️ 업그레이드 전에 알아둘 것

- 지오 우선 허용 IP와 URI 차단 예외 IP가 입력한 범위대로만 적용됩니다. 예전에는 `/32`가 같은 `/24` 전체에, `/20`이 `/16` 전체에 적용됐습니다. 넓게 적용되던 범위로만 들어오던 클라이언트는 이제 막힙니다. 반대로 IPv6 대역, 다른 표기의 IPv6 주소, `::ffff:` 주소, `/8`보다 넓은 IPv4 대역(`0.0.0.0/0` 포함)은 이제 실제로 적용됩니다. 그런 항목은 업그레이드 후 첫 기동 때 API 컨테이너 로그에 한 번 나옵니다.
- ForwardAuth(Authelia·Authentik 등) 로그인이 있는 호스트에서는 URI 차단 예외 IP도 차단된 경로에 들어갈 때 로그인합니다. 그 호스트의 인증 예외 경로 아래는 예전처럼 로그인 없이 통과합니다.
- 레이트 리밋 카운터가 업그레이드 때 한 번 초기화됩니다. Advanced Config나 사용자 정의 HTTP 설정에서 `rate_…`, `global_req_limit`, `global_conn_limit`를 쓰고 있다면 업그레이드 후 nginx 컨테이너를 한 번 재시작하고 새 이름(`npg_rl_…`, `npg_global_req`, `npg_global_conn`)으로 바꾸세요. 어디서 쓰는지는 API 컨테이너 로그에 나옵니다.
- nginx가 새 설정을 받아들이지 않으면 이제 저장 결과가 409로 알려 줍니다(변경은 저장된 상태). 이유가 "포트 사용 중"이면 nginx를 재시작하지 말고 포트를 비우거나 호스트를 바꾸세요. 그 상태에서는 nginx가 다시 시작되지 않습니다.

## 고침

- 레이트 리밋 예외나 전역 신뢰 IP를 처음 넣거나 모두 뺀 뒤, nginx를 재시작할 때까지 이후 설정 변경이 반영되지 않던 문제.
- nginx가 새 설정을 거부해도 저장이 성공으로 보이던 문제.
- 접근 목록 저장이 중간에 실패하면 규칙 일부가 사라지던 문제.
- 접근 목록 변경이 감사 로그에 남지 않던 문제, 쓰기 권한이 없는 역할에 접근 목록 편집 버튼이 보이던 문제.

## ⚠️ Read before upgrading

- Geo priority allow IPs and URI block exception IPs now apply exactly the range entered. Before, a `/32` applied to its whole `/24` and a `/20` to its `/16`; clients that only got in through that wider match are now blocked. IPv6 ranges, IPv6 addresses in another notation, `::ffff:` addresses and IPv4 ranges wider than `/8` (including `0.0.0.0/0`) now apply for the first time. The first start after the upgrade lists such entries once in the API container log.
- On hosts with a ForwardAuth login (Authelia, Authentik, …), URI block exception IPs now also log in to reach blocked paths. Paths under the host's auth bypass paths still pass without login, as before.
- Rate limit counters reset once on upgrade. If Advanced Config or the custom HTTP config uses `rate_…`, `global_req_limit` or `global_conn_limit`, restart the nginx container once after upgrading and switch to the new names (`npg_rl_…`, `npg_global_req`, `npg_global_conn`). The API container log says where they are used.
- When nginx does not accept a new configuration, the save now answers 409 (the change is saved). If the reason is a port in use, do not restart nginx: free the port or change the host first, because nginx cannot start again while it is taken.

## Fixed

- After adding the first rate limit exception or global trusted IP, or removing the last one, later changes were not applied until nginx restarted.
- A save looked successful when nginx refused the new configuration.
- An access list save that failed part-way lost some of its rules.
- Access list changes were not in the audit log, and roles without write access saw the access list edit buttons.
